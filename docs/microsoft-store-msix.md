# Microsoft Store delivery (MSIX)

Store policy 10.2.9 requires EXE/MSI submissions to be Authenticode-signed with a
certificate that chains to the Microsoft Trusted Root Program. The Store does **not**
re-sign EXE/MSI installers, but it **does** re-sign MSIX packages during publishing.
PhoneDesk therefore ships to the Store as an MSIX package and keeps the Inno Setup
installer for GitHub Releases and the in-app updater.

## What the build produces

`scripts/package-msix.ps1` turns the self-contained `win-x64` publish output into
`phonedesk-win-x64.msix`:

1. Copies the publish output plus `installer/msix/Assets` into a staging folder.
2. Removes `*.pdb` and the NuGet leftovers that `Save-Module` leaves inside each
   bundled module (`[Content_Types].xml`, `_rels/`, `package/`, `*.nuspec`).
   `[Content_Types].xml` is a reserved OPC name and makes `makeappx` fail with
   `0x8007007b`.
3. Fills the placeholders in `installer/msix/AppxManifest.xml` and runs
   `makeappx.exe pack` from the Windows SDK.

The package is **unsigned on purpose**. `-TestCertificate` signs it with a throwaway
self-signed certificate for local sideload tests only.

The manifest declares a full-trust desktop app (`EntryPoint="Windows.FullTrustApplication"`,
`runFullTrust`), `Windows.Desktop` 10.0.17763 as the floor, and the T-Pad brand assets
generated by `assets/generate-icons.py` (`installer/msix/Assets`).

## Package identity

Partner Center assigns the identity when the MSIX product is created
(Product management > Product identity):

| Manifest attribute | Partner Center field | CI source |
| --- | --- | --- |
| `Identity/@Name` | Package/Identity/Name | repository variable `MSIX_IDENTITY_NAME` |
| `Identity/@Publisher` | Package/Identity/Publisher (`CN=<GUID>`) | repository variable `MSIX_PUBLISHER` |
| `Properties/PublisherDisplayName` | Publisher display name | script default `Patrik Lleshaj` |

Without the variables the release build still produces a package with the development
identity `PhoneDesk.Dev` / `CN=PhoneDesk Development`, which the Store rejects. Set both
variables before the first Store release.

The package version is `X.Y.Z.0`; the Store reserves the fourth part.

## Runtime behaviour in the Store build

`WindowsInstallationContext` detects package identity through `GetCurrentPackageFullName`.
When it reports a packaged install, the composition root registers
`StoreManagedUpdateCheckService`, so the in-app GitHub updater never offers a download:
updates arrive through the Store. Everything else is unchanged. Per-user data written to
`%LOCALAPPDATA%\PhoneDesk` is virtualised by Windows into the package's `LocalCache`,
so a Store install does not share preferences or audit logs with an Inno Setup install
on the same machine.

## Local sideload test

```powershell
dotnet publish phonedesk.csproj -c Release -r win-x64 --self-contained -o ./publish/win-x64
./scripts/package-msix.ps1 -PublishDir ./publish/win-x64 -Version 3.34.0 -OutputDir ./dist -TestCertificate
# elevated: trust the throwaway certificate on this machine
Import-Certificate -FilePath ./dist/phonedesk-win-x64.test.cer -CertStoreLocation Cert:\LocalMachine\TrustedPeople
# normal user
Add-AppxPackage -Path ./dist/phonedesk-win-x64.msix
Get-AppxPackage PhoneDesk.Dev | Remove-AppxPackage   # clean up afterwards
```

The script keeps the test certificate in `Cert:\CurrentUser\My` (friendly name
"PhoneDesk MSIX test signing") and reuses it on later builds, so the elevated import is a
one-time step per machine. Remove it from both stores after testing.

Sideload findings (3.33.0 test build, shipped as 3.34.0): the app starts with package identity from
`C:\Program Files\WindowsApps`, the bundled MicrosoftTeams 8.0.0 loads from the package,
Teams sign-in works, and preferences written by the Inno Setup install are visible
read-through. The first Graph sign-in failed on a machine with a user-scope
Microsoft.Graph.Authentication 2.41.2: a name-only `Import-Module` picked it over the bundled
2.41.1 and the other bundled Graph modules then failed with "Microsoft.Graph.Authentication.Loader
... is already loaded". This is not MSIX-specific; the Graph connect script now imports every
bundled Graph module by manifest path (same pattern as Teams), covered by
`GraphModuleSelectionTests`.

## Partner Center steps

1. The current EXE product (`53a8f446-bbf3-4c01-9156-3ef5b44aaf57`, Store ID `XPFD7Z5V0SHCCH`)
   owns the reserved name "PhoneDesk". Partner Center only allows one product per name,
   so the EXE product has to release the name (delete the product, or rename it) before the
   MSIX product can reserve "PhoneDesk". The Store ID and deep link change with the new product.
2. Create a new app (type MSIX / packaged app), reserve the name, and copy the
   Package/Identity/Name and Publisher values into the repository variables above.
3. Run a release. Upload `phonedesk-win-x64.msix` from the GitHub release on the Packages page.
   No package URL and no gh-pages copy is needed for MSIX.
4. Re-create the listing (description, screenshots from `GENERATE_SCREENSHOTS=1 SCREENSHOT_FRAMELESS=1`,
   age rating, properties, privacy policy URL) and submit.

Once the MSIX product is live, the `publish-store-package.yml` workflow and the `store/`
folder on `gh-pages` are no longer needed.
